# Technical decisions

Short log of choices that `CLAUDE.md` left open or that changed. One row per decision, with a number, a date and a one-line reason. To change a decision, add a new row that supersedes the old one. Do not delete old rows.

| Id | Date | Decision | Reason |
|---|---|---|---|
| D-001 | 2026-10-29 | Data access with **Kysely** + `kysely-codegen` (types generated from the database). Migrations are **plain numbered SQL files**, run by a small script in `apps/api`. | The data model has a lot of hand-written SQL (RLS, triggers, routines with `FOR UPDATE`, `SET LOCAL`). Kysely keeps the transaction and the RLS context explicit and does not hide the SQL. |
| D-002 | 2026-10-29 | **Tailwind CSS v4** with shadcn/ui. | The starter tokens in `CLAUDE.md` already use `@theme inline`. |
| D-003 | 2026-10-29 | **Storybook** in `apps/web` to build and approve the design system. | Tiago approves each component on a single page, without assembling a screen. |
| D-004 | 2026-10-29 | **Vitest** for unit and integration tests, **Testcontainers** for a real Postgres, **Playwright** for flows and screenshots. | Matches the stack in `CLAUDE.md`. |
| D-005 | 2026-10-29 | Local Postgres via **Docker Compose** (`docker-compose.yml` at the root, Postgres 16). | One command gives everyone the same database. |
| D-006 | 2026-10-29 | shadcn components live in `apps/web/src/components/ui/`. Product composites (`ProgramCard`, `BottomNav`, ...) live in `apps/web/src/components/product/`. | Separates base from product-specific. |
| D-007 | 2026-10-29 | **Everything is in English**: code, identifiers, file and folder names, routes, database objects, commit messages, code comments and documentation filenames. **Only text shown to the end user is Brazilian Portuguese.** That text lives in `apps/web/src/messages/pt-BR.ts` (keys in English), and in the API's message module for errors and e-mails. | Project rule from Tiago. |
| D-008 | 2026-10-29 | Customer screens start with **fixed data** (`fixtures`) behind TanStack Query hooks. Each screen is wired to the API later, in its own task. | Tiago approves the visual early, and swapping in the API does not touch the screens. |
| D-009 | 2026-10-29 | `docs/design/screens/*.dc.html` are **read-only** and act as a specification. Their file names are the original Portuguese names exported from the design tool and stay as they are. Do not try to render them (they depend on a `support.js` that is not in the repository). | Avoids wasted effort and accidental edits to the design source. |
| D-010 | 2026-10-29 | Business rule ids keep the prefix `RN-` (Portuguese for "business rule") because they are identifiers used across the documents. Test names use them, for example `it('RN-VAL-02: expired cycle loses its stamps', ...)`. | Renaming ids would touch every document. Can be changed later with a single search and replace. |
| D-011 | 2026-10-29 | Routes are in English. Customer: `/`, `/my-qr`, `/profile`, `/sign-in`, `/sign-in/code`, `/sign-up`, `/welcome`, `/s/:slug`. Staff: `/staff/...`. Owner: `/owner/...`. | Follows D-007. |
| D-012 | 2026-10-29 | Web build tooling: **Vite 8** with **Vitest 5** (same Vite major), `@fontsource-variable/manrope` for the local font, `vite-plugin-pwa` for the manifest and service worker, `@storybook/react-vite` 10 with the a11y addon. Playwright lives at the repository root and is used only for evidence screenshots (`apps/web/scripts/`). | Vitest 3 pulled a second Vite copy and broke type checking of `vite.config.ts`. Fontsource keeps the font in the bundle with no CDN. |
| D-013 | 2026-10-29 | Type scale is exposed as Tailwind theme tokens (`text-display`, `text-title-1` ... `text-overline`), each with size, line height and weight from `CLAUDE.md`. Uppercase for `overline` and `tabular-nums` for `metric` are applied with utility classes at the call site. | One class per style, no arbitrary pixel values in components. |
| D-014 | 2026-10-30 | **Every base component comes from the shadcn CLI** (`pnpm exec shadcn add <name>`, CLI is a dev dependency), then restyled with the product tokens. Product composites (`StampSeal`, `ProgramCard`, `TextField`, ...) are built on top of them and never re-implement what shadcn has. shadcn files stay flat in `components/ui/` with kebab-case names, as the CLI creates them (`button.tsx`), with stories and tests beside them. Composites live in `components/product/<Name>/`. Supersedes the folder-per-component detail of D-006. | Tiago asked for one standard. The CLI imports `cn` from the `cn` npm package by mistake, so the import is changed to `@/lib/utils` after each `add`. |
| D-015 | 2026-10-30 | Two shades from the design files are tokens: `--soft` `#D9D4C6` (inactive step dot) and `--input-disabled` `#C9C4B6` (disabled radio border). Also `shadow-card-stack` (the soft shadow of stacked cards from `CLAUDE.md`). | Components may not hold raw hex values. |
| D-016 | 2026-10-30 | Phase A design system (T03 to T07) was built and delivered as a single batch, at Tiago's request, to speed up. The rule of one task at a time stays for the other phases unless Tiago says otherwise. | Tiago's decision. |
| D-017 | 2026-10-30 | The welcome illustration (`OnboardingArt`) uses the soft shadow of the design (`shadow-art`, token in `index.css`), even though `CLAUDE.md` prefers borders to shadows. Its elements are anchored to the center of the art area, not to the top-left, so it fits 360 x 640 screens. On 390 x 844 it is identical to the design. | The design file specifies the shadow. Anchoring avoids clipping on short screens. |
| D-018 | 2026-10-31 | On the welcome screens the white sheet is as tall as its content (24 px between text and dots, 16 px between dots and button, 32 px below the button) and the illustration takes the remaining height. The design has a fixed 336 px sheet with the three parts spread out. | Tiago's request: no empty space between text, dots and button. |
| D-019 | 2026-10-31 | New routes: `/profile-choice` (screen 02, after the welcome) and `/staff/sign-in` (entry of the staff area, placeholder until M3). Sheets use the shadcn `Sheet` (Radix Dialog) restyled as a bottom sheet, rendered inside the phone frame (`FrameContainer`), closing with the X in the corner (`IconButton`) and with Escape. When a sheet opens, the focus goes to the sheet and the first Tab goes to its first action. | D-011 did not list these routes. Sheets must stay inside the 390 px phone on wide screens. |
| D-020 | 2026-10-31 | The second option of the profile choice (screen 02) reads "Sou prestador", not "Sou do salão" as in `Escolha-Perfil.dc.html` (read-only). Also "do negócio" replaces "do salão" in the hint of screen 02, and "em cada negócio" replaces "em cada salão" in welcome step 2 (`Onboarding-2.dc.html`). From now on, customer copy copied from the design says "negócio" where the design says "salão". | Tiago: the product serves more than salons, so the text should not say "salão". |
| D-021 | 2026-10-31 | Phase B sign-in is simulated in `apps/web/src/data/auth.ts` with the real rules and the error codes of `API.md`: only +55 mobiles (RN-AUT-01), 5 wrong attempts then a 15 minute lock (RN-AUT-02), 3 requests per number (RN-AUT-03), same answer for new and existing numbers (RN-AUT-05). The code that is accepted is `123456`. The number `+55 11 90000-0000` (Maria) is the existing account; any other number is a new account and goes to the name step (RN-ENT-07). In-text links (`TextLink`) are amber ink, bold and underlined. | Lets the screens handle every case now, and Phase C only swaps the two functions for API calls. |
